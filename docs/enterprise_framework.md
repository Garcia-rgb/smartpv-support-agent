# 企业运行框架（v1.10.0）

本版本先补齐管理和运行能力，数据质量、更多协议版式与现场验收后续推进。

## 管理员入口

登录 admin 后，右上角进入「管理中心」：

- 运行概况：文档、账号、会话、消息、工单和负面反馈数量，模型配置及最近备份。
- 资料管理：分页查看导入资料，修改资料版本和普通/隐私库归属，停用或重新启用。停用资料会从检索、检索缓存和刷题题库读取中排除；历史回答不改写。
- 操作记录：查看账号、资料、备份、题目讲解和工具等既有审计事件。界面不展示密钥、密码和完整提问。
- 备份：本机 SQLite 使用在线一致性快照，并打包 knowledge_base 原件和 SHA256 校验清单。备份只在本机保留，admin 可以下载；不打包项目 .env。

user 继续使用问答、刷题、点表、工单及自己的会话，不具备管理接口权限。刷题结果与识别文字保存到会话，原截图仅在内存处理。所有资料管理和备份接口都需要真实 admin 登录及写请求校验。

## 运行与诊断

- `/health` 查看服务模式；`/ready` 实际检查数据库连接，可用于部署就绪探测。
- `.logs/service.log` 保存请求编号、路径、状态、耗时与异常栈，按 5 MB 轮转保留 5 份。请求日志不保存请求正文。
- 正式环境设置 `APP_ENV=production`，身份验证必须开启，`CONFIRMATION_SECRET` 至少 32 个字符且独立随机生成；正式 PostgreSQL 密码至少 16 个字符。浏览器使用 HTTPS，登录 Cookie 在正式环境只通过 HTTPS 发送。
- Docker 已有健康检查和异常重启；新增 operations_data 卷保留日志、knowledge_base_data 卷保留上传原件。API 默认绑定本机回环地址，由企业 HTTPS 反向代理发布。
- 本机依赖环境可运行 `scripts/setup_client.ps1 -Python <已安装Python路径>` 创建项目 .venv、安装依赖并生成桌面入口；这是准备工具，本次没有替用户重新安装依赖。

## 备份和恢复

网页备份适用于当前本机 SQLite；PostgreSQL 采用其原生 `pg_dump`/`pg_restore`，不混用文件快照。备份包含内部资料和账号密码哈希，应保存在管理员可访问的目录。

手动或交给 Windows 任务计划运行：

```powershell
python scripts/backup_project.py
```

恢复到新的目录，避免覆盖运行中的数据库：

```powershell
python scripts/restore_backup.py .backups/<备份文件名>.zip --output recovery/2026-10-08
```

工具先验证全部文件校验值和路径，再恢复原件和数据库，并检查数据库完整性；恢复库会清除旧登录会话，需要重新登录。管理员应在新目录验收资料和账号，再停止原服务、留存原库、调整 DATABASE_URL 指向恢复库，并设置 KNOWLEDGE_BASE_DIR 指向恢复后的资料目录，最后重启服务。恢复工具不覆盖原系统。

定时备份通过系统任务计划调用备份脚本；本次没有创建后台计划。备份保留时间与异机副本由实际部署时决定。恢复时模型密钥由企业单独配置。

管理中心、权限、资料生命周期、会话记录、审计、备份恢复和运行诊断已经落地；这不代表回答内容或点表经过现场验收。本次没有部署企业服务器、配置证书或迁移到 PostgreSQL。以后按实际人数和基础设施调整部署，业务数据逐步补充。
