# 企业场景建设计划

## 三个首批用途

1. **托管平台排障**：用户输入现象、设备型号、软件版本和现场条件；系统优先检索工作记录与交付资料，给出可核对的排查步骤、引用来源和未确认项。涉及设备控制、保护定值、账号等操作时，不直接代替现场审批。
2. **HCSA 学习与题目解释**：用户粘贴题目或选择模拟题；系统引用 HCSA V2 教材资料，解释答案、错误选项和适用版本。当前模拟卷标题写“40题”，实际有 45 个编号；账号密码相关两题不保存具体凭据。
3. **点表制作**：用户提供设备协议和目标平台的成功导入模板；系统先提取候选点位，再展示地址、功能码、数据类型、字节/字序、倍率、单位、遥信/遥测/遥控/遥调等字段的依据与缺口。人工核对后导出与目标平台一致的文件；禁止猜造寄存器或控制值。

- `knowledge_base/托管平台工作记录`：32 个原文件，其中 17 份文字资料已进入 `work_records` 检索分组。图片和录音保留原件，尚未 OCR/转写。
- `knowledge_base/HCSA-V2`：V2 教材、19 份分卷、索引及备考资料已保留。本地数据库已有 20 份 HCSA 分卷/补充文档；另将 45 道模拟题和答案逐题配对后导入 `smartpv_v2`。
- `knowledge_base/课程`：前一阶段复制的 23 个原文件，其中 22 份可读文档已导入。
- `knowledge_base/点表规则`：已保留两份点表生成工具说明、常见设备点表、智能空开协议、成功导入的参考 CSV；两份工具说明已导入 `pointtable_rules` 检索分组。此前“制作智能空开点表”任务提供了智能空开的实际联调案例。

## 下一阶段的可交付项

1. **本地问答与场景分流**：普通/隐私资料分流已接入；下一步验证本机轻量生成模型，对排障、刷题、点表分别限定资料分组和回答格式；同一问题返回可点击的来源与版本。
2. **排障验证**：从工作记录抽取一批真实案例，逐题核对检索来源、步骤和不能确定的地方；建立验收清单。
3. **刷题验证**：按 45 道模拟题抽样核对答案和解释，区分教材原文、整理稿和推断，不把整理稿当作唯一权威来源。
4. **点表最小工具**：先支持一类实际协议和一份已成功导入的目标模板，输出预览、校验报告和导入文件；再逐步扩展其他协议及设备。

## 本地处理设计

```text
用户界面 → 场景选择 → 本地检索（按资料分组与版本） → 本机生成模型 → 带引用的回答
                                       ↘ 无可靠依据时追问或转人工
设备协议 + 成功导入模板 → 点位抽取 → 字段核对与校验 → 人工确认 → 点表文件
```

- 本地数据库和 ONNX 向量模型已经运行；公司文档、图片、录音及转换稿只保存在本机的 `knowledge_base/`。
- 隐私问答的生成模型只允许使用本机回环地址。普通资料经审核后可使用远程模型，远程请求只带当前普通问题和普通资料片段，不带聊天历史。`.env` 当前启用隐私分流，远程模型开关仅对普通问题有效。
- 没有本机生成模型时，界面应明确提示“仅展示检索依据”，不能把规则拼接的片段冒充完整解释。
- 验收时检查本地模型断开外网仍能完成排障和题目解释；回答必须能追溯到文档、章节、版本。点表生成还要有导入测试及现场对点记录。

## 上线前必须确认

- 用户已确认公司内部资料暂不允许发送到 DeepSeek 等外部模型；另同意华为公开手册与 HCSA 课程资料经审核进入普通库。旧资料默认隐私，普通问答可使用 DeepSeek，隐私问答只在本地处理。本机生成模型和公开搜索接口仍需实际部署与验收。
- 当前图片和会议录音未转成可搜索文字，Word/PPT 中的纯图片也未做 OCR。
- 点表导入格式与规则依赖目标平台及具体设备协议版本。不能只凭通用模板生成可投运点表，必须用真实平台导入和现场对点结果验收。
