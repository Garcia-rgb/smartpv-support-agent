# 现场排查

版本：1.0.0

## 触发

用户描述设备通信、采集数据、告警或运行异常；在同一聊天中持续反馈检查结果。

## 执行流程

1. 从当前问题及本会话用户描述提取厂家型号、现象、已完成检查及结果、无效尝试、约束。助手建议不等于用户已执行。
2. 使用本机知识检索获取适用资料，先核对厂家、型号和场景。型号未覆盖只提供通用核查，不套用其他型号参数。
3. 有报文或寄存器解码需求时使用实际工具计算；缺报文、方向、数据类型或字序就追问。
4. 给出当前判断及最多三个下一步；按最容易确认、最能区分原因的检查排序。
5. 用户反馈后更新判断，保留仍然有效的检查事实，避免重复已完成无效步骤。明确换问题时开始新问题状态。

## 约束

- 区分已确认事实、根据资料提出的可能原因、尚未确认的信息。
- 不把截图空白字段直接认定为设备硬件故障，也不把陈旧数据当实时数据。
- 无资料支持时说明无法确认根因，仍可给通用只读核查建议，明确区分资料事实与推测；不能只回复资料不足。
- 平台数值异常先比较同一时刻本机和平台值，检查采集时间、设备关联、点位映射、倍率与字序；不要未经核对就改配置。
- 不直接控制现场设备。复位、恢复出厂、修改地址及控制点写入必须有适用依据和现场确认。
- 未解决记录中的失败操作不能当作成功处理方案。

## 输出

优先用“当前判断 / 下一步 / 需补充”简短组织回答；无必要不重复已经确认的基础信息。
