# 光伏电站技术支持 Agent

[![version](https://img.shields.io/badge/version-1.10.2-blue)](CHANGELOG.md)
[![python](https://img.shields.io/badge/python-3.11%2B-3776ab)](pyproject.toml)
[![license](https://img.shields.io/badge/license-MIT-yellow)](LICENSE)

面向光伏服务人员的技术支持工具，集中处理 **现场问题排查、课程刷题讲解和点表制作**。
支持文字输入、上传或粘贴截图，并提供 admin / user 账号、资料管理和本机备份。

当前版本 **v1.10.2**，适合在 Windows 本机试用和逐步补充业务资料。企业运行框架已搭建，回答质量与协议解析仍需结合实际资料和现场结果验收。

## 主要功能

| 业务 | 当前支持 |
|---|---|
| 现场问题 | 从本机资料库检索依据，配置远程模型后整理回答；显示资料引用，支持追问和反馈 |
| 学习刷题 | 识别题干及选项，结合题库、检索资料和模型给出选项与解释；依据不足时提示核对 |
| 点表制作 | 选择南向或北向，上传设备协议 Word / 文字版 PDF，解析候选点位、手动补充字段并导出 CSV |
| 工单 | 在项目内创建和查看工单，写入前人工确认；尚未对接企业实际工单系统 |
| 账号权限 | admin 管理账号与资料；user 使用业务功能、查看自己的会话和工单、修改密码 |
| 管理中心 | 运行概况、资料版本及分库管理、启用/停用、操作记录、SQLite 备份下载 |

### 文字和图片使用同一个入口

输入文字，点击「上传图片」，或直接在输入框粘贴截图。图片先在本机 OCR 成文字，再按内容判断：

- 有明确题目和选项结构的内容进入刷题讲解。
- 客户聊天、告警和现场描述进入技术问答。
- 识别文字可核对、修改后重新提交。

当前图片处理以文字识别为主，不能凭纯设备照片判断故障。分类和识别可能出错，需要核对识别结果。

### 点表需要现场核对

协议解析在本机进行，协议文件不送给 DeepSeek。支持 `.docx`、文字版 PDF 和部分旧 `.doc` 文件；扫描件需先做 OCR。不同协议版式可能需要人工补点。

生成前可修改点位及现场字段。南向地址与北向平台点号分别填写；地址基数、字序、倍率、控制值和设备信息需按现场协议核实。输出为 CSV，当前不在服务端保存生成文件。

## 数据与模型如何处理

**本机运行不等于所有数据都留在本机。** 数据库、资料原件、检索和 OCR 在本机；启用远程模型后，部分问答内容会发送到配置的模型服务。

| 内容 | 处理方式 |
|---|---|
| 账号、会话、工单、反馈 | 保存到配置的数据库；本机默认 SQLite |
| 导入资料 | 在本机切分、生成向量并检索；新上传原件保存到 `knowledge_base/` |
| 普通 / 隐私资料库 | 用于分类和控制检索范围；目前两类问答都可调用 DeepSeek，分库本身不阻止外发 |
| 分流后的资料问答 | 将本次问题和命中片段交给远程模型整理，该路径不附带聊天历史 |
| 工具调用等其他模型路径 | 使用独立的 Agent 流程，可能携带近期会话上下文；不能把所有路径都视为无历史外发 |
| 题目截图 | 先本机 OCR，模型兜底可能发送识别出的题目、选项和资料片段 |
| 公开网页搜索 | 需另外配置搜索服务，只发送白名单产品和通用技术词；DeepSeek API 本身不自动联网搜索 |

新克隆项目的 `.env.example` **默认关闭远程模型**；未配置时使用本地规则和检索摘要，生成能力有限。启用远程服务前应确定资料使用范围。关闭远程调用可设置 `ALLOW_REMOTE_LLM=false`。

真实资料、模型密钥、数据库、日志和备份不随仓库分发。详细说明见 [资料分流说明](docs/privacy_routing.md)。

## Windows 本机快速开始

需要 Python 3.11 或更高版本。在项目目录中运行以下步骤；已有环境和 admin 账号可跳过对应初始化步骤。

### 1. 下载和安装

```powershell
git clone https://github.com/Garcia-rgb/smartpv-support-agent.git
cd smartpv-support-agent
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[quiz]"
Copy-Item .env.example .env
```

`quiz` 安装本机图片识别所需依赖。首次使用 OCR 时可能需要下载模型文件，请预留网络和磁盘空间。

### 2. 配置模型（可选）

编辑 `.env`，远程问答需要同时配置：

```dotenv
ALLOW_REMOTE_LLM=true
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=<你的账号可用的模型名称>
LLM_API_KEY=<你的 API Key>
PRIVACY_ROUTING_ENABLED=true
```

模型名称以服务商及账号实际可用配置为准。不要将真实 Key 写入代码、README 或提交到 Git。

### 3. 创建管理员并启动

```powershell
.\.venv\Scripts\python.exe scripts/create_admin.py --generate
.\.venv\Scripts\python.exe scripts/start_client.py
```

记下首次显示的 admin 密码，登录后修改密码。已有 admin 时，创建脚本不会覆盖账号或密码。

默认地址为 **http://127.0.0.1:8000/**；端口被占用时，启动器会尝试其他端口，以窗口显示的地址为准。启动窗口需要保持运行；电脑关机或休眠时服务不可用。

### 4. 添加资料和用户

- admin 登录后，在「管理中心」导入资料，核对所属库、资料版本和启用状态。
- 在「管理用户」创建 user 账号，将一次性初始密码交给对应人员。
- 仓库不包含业务资料，需自行导入后才能验证检索和答题效果。

需要桌面启动入口时运行：

```powershell
.\.venv\Scripts\python.exe scripts/create_desktop_launcher.py
```

生成的 `.cmd` 绑定当前项目路径和 Python 环境；移动项目或更换环境后需要重新生成。当前启动器默认仅本机访问，不会自动向局域网开放。

## 技术栈

| 层次 | 技术 |
|---|---|
| 网页 | HTML / CSS / 原生 JavaScript，目前未使用 Vue 或 React |
| 后端 | Python、FastAPI、Pydantic、Uvicorn |
| 数据存储 | SQLAlchemy；本机 SQLite，可选 PostgreSQL / pgvector |
| 检索 | 字符及关键词打分、向量检索、场景元数据与资料版本提示 |
| 本机推理 | 可选 ONNX Runtime 语义向量；RapidOCR 图片文字识别 |
| 问答与流程 | OpenAI 兼容模型接口、工具调用、LangGraph 状态流程、人工确认 |
| 运行保障 | 服务端会话和角色权限、审计、轮转日志、缓存与限流；可选 Redis |
| 部署与验证 | Docker Compose、pytest、Ruff、离线评测工具 |

默认 `hash` 向量用于轻量试用，不具备语义模型的理解能力。启用 ONNX 需安装 `semantic` 可选依赖并另行准备模型文件；切换向量后端后需重新构建对应语料向量，操作前先备份。

## 管理、备份与部署

本机默认持久化位置：

- `support_agent.db`：账号、会话、资料片段等数据库内容。
- `knowledge_base/`：资料原件及本机业务资料。
- `.backups/`：管理员创建的备份。
- `.logs/`：轮转运行日志。

admin 可在管理中心创建和下载 SQLite 在线快照与资料备份。恢复工具会验证校验值、恢复到新目录并撤销旧登录会话。备份含内部资料和账号密码哈希，应妥善保存。当前没有自动创建定时备份任务。

`/health` 查看服务状态，`/ready` 检查数据库就绪。Docker Compose 提供 PostgreSQL、Redis 和持久化目录配置，正式部署还需落实 HTTPS、独立密钥、备份策略及实际验收。本项目尚未完成企业服务器部署。

操作步骤见 [企业运行框架](docs/enterprise_framework.md) 和 [部署说明](docs/deployment.md)。

## 使用边界

项目用于辅助技术支持和学习。回答需要结合资料版本、设备型号及实际现场核实；点表需完成对点后再导入生产系统。设备档案和工单能力目前属于项目内的业务框架，未自动连接企业真实系统。

### 一、项目介绍

#### 1. 请介绍一下这个项目。

这是一个面向光伏服务人员的技术支持助手，主要解决三个问题：现场故障排查、认证课程刷题讲解和设备点表制作。

用户可以输入文字或上传、粘贴截图。后端使用 Python 和 FastAPI，结合本机资料检索与 DeepSeek 生成回答，并提供 admin / user 权限、会话记录、资料管理、操作审计和备份恢复。目前主要在 Windows 本机运行。

#### 2. 为什么要做这个项目？直接用大模型不行吗？

通用大模型不了解公司的工作记录、设备协议和特定版本资料，直接提问容易出现依据不清楚、型号不匹配的问题。

这个项目先从业务资料中找依据，再整理回答并展示引用。同时加入点表制作和工单等流程，让助手能够完成具体业务任务。

#### 3. 这个项目算 Agent 还是普通聊天机器人？

项目同时包含明确的业务流程与工具调用流程。资料问答和刷题主要采用检索、判断和生成流程；设备查询、工单等任务使用工具调用，由模型提出申请，后端负责执行和状态控制。

涉及写操作时需要人工确认，模型不能直接决定操作已经完成。它具备 Agent 能力，但没有让所有业务都依赖模型自主规划。

#### 4. 你在这个项目中负责了什么？

这题需要按个人实际参与情况回答。例如：我负责业务需求梳理、技术方案选择、开发推进和验收，包括统一文字与图片输入、资料检索、刷题讲解、协议点表、账号权限和运行管理框架。

开发中使用 AI 编程工具辅助实现，重点负责明确业务规则、检查实现和验证案例。若被追问代码，应能解释调用关系、设计理由和验证方法，不应将不了解的实现表述为独立完成。

### 二、技术架构

#### 5. 项目用了哪些技术栈？

前端使用 HTML、CSS 和原生 JavaScript；后端使用 FastAPI、Pydantic 和 Uvicorn。数据库通过 SQLAlchemy 访问，本机默认 SQLite，部署配置支持 PostgreSQL。

检索支持关键词与向量结合，语义向量可使用 ONNX Runtime，OCR 使用 RapidOCR。模型通过 OpenAI 兼容接口接入，工具和状态流程使用 Agent 工具调用与 LangGraph，缓存和限流可以接入 Redis。

#### 6. 一次问题请求的处理过程是什么？

先验证登录身份和会话权限。图片输入先在本机 OCR 成文字，再判断是学习题目还是现场问题。

现场问答检索相关片段，配置了远程模型时将问题和资料交给模型整理，随后保存回答与引用。工具请求进入工具流程，写操作需要人工确认。不同业务采用不同路径，并非所有请求都经过同一处理链。

#### 7. 为什么先用 SQLite，不直接用 PostgreSQL？

当前主要在一台电脑上试用，SQLite 不需要单独维护数据库服务，部署成本低，也方便备份和功能验证。

多用户写入增加或者需要多实例部署时，可以迁移到 PostgreSQL，但还需要验证表结构、数据与备份恢复，不能只修改连接地址就认为完成了迁移。

#### 8. 为什么前端没有使用 Vue 或 React？

初期页面规模较小，主要是聊天、上传和管理弹窗，原生 JavaScript 可以较快验证业务。

随着页面状态、组件复用和权限交互增加，现有前端维护成本会提高。是否迁移应根据实际复杂度决定，目前项目没有完成这项迁移。

### 三、资料检索与回答

#### 9. RAG 是什么？项目为什么使用它？

RAG 是先检索资料，再让模型依据检索结果回答。设备手册和工作资料持续更新，回答也需要追溯来源，因此适合采用这种方式。

相比把知识写死在提示词里，资料更新和引用展示更方便。不过 RAG 不能保证回答正确，检索质量、资料版本和模型是否遵循依据都会影响结果。

#### 10. 资料怎么变成可以检索的内容？

导入后先抽取文字，再切分成片段，生成对应向量，并保存来源与版本等信息。

提问时综合文字匹配、向量相似度及设备型号、场景等元数据排序，选择相关片段作为依据。片段太短容易丢失上下文，太长则会混入无关内容，需要根据资料结构调整。

#### 11. ONNX 和 DeepSeek 分别负责什么？

ONNX Runtime 用于本机推理，在这里主要承担语义向量计算，帮助检索资料，不负责生成完整回答。DeepSeek 负责理解问题、整理片段和生成解释。

实际流程由后端调用本机检索，再按配置调用 DeepSeek，并非 DeepSeek 直接访问电脑上的 ONNX 或数据库。

#### 12. 没找到资料时怎么处理？如何减少幻觉？

通过显示引用、要求模型依据资料回答，以及依据不足时提示补充信息或无法确定，降低错误回答概率。

刷题还会校验返回选项是否属于题目给出的范围，输出格式异常时降级处理。这些措施只能降低风险，设备操作和点表导入仍需人工核对，不能把模型回答作为自动执行指令。

#### 13. 多个版本的资料说法不一致怎么办？

项目保存资料版本，并支持提示不同版本的检索依据。管理员可以停用旧资料，使其不再参与后续检索。

实际使用仍要结合型号、固件和现场版本判断适用性，目前没有实现完整的文档审批与版本适用性管理流程。

### 四、图片与业务工具

#### 14. 如何避免把客户截图识别成考试题？

图片先统一 OCR，不直接把所有图片送入刷题接口。只有满足明确题目结构，例如题型标记、判断选项或完整的多选项问句，才进入刷题。

含客户、现场和工单等线索的内容会保守处理。OCR 与分类均可能出错，所以用户可以查看、修改识别文字后重新提交。

#### 15. 点表制作为什么没有完全交给大模型？

点表的地址、数据类型、倍率和控制值要求准确，错误可能造成现场读取或控制异常。

目前在本机解析协议、抽取候选点位，再由用户补充现场字段、修改和核对，最后导出 CSV，便于检查字段来源。协议版式不同仍可能需要人工补点，生成后必须完成现场对点。

#### 16. 南向和北向点表有什么区别？

在这个项目的业务语境中，南向主要面向设备接入，关注设备协议地址和现场通信参数；北向主要面向平台对接，关注平台点号和字段映射。

设备协议中的 Modbus 地址不自动等于平台点号，所以项目要求分别填写、核对，不能直接套用。

### 五、权限与数据处理

#### 17. admin 和 user 的权限怎么实现？

权限由后端检查，前端隐藏按钮只是交互表现。服务端根据登录会话确定用户，再检查角色和资源归属。

admin 管理账号、资料和备份；user 使用业务功能，并访问自己的会话和工单。客户端传来的用户编号不能直接作为身份依据，避免修改编号访问他人数据。

#### 18. 密码和登录信息怎么保存？

密码以哈希形式保存，不保存明文。登录后通过服务端会话识别用户；停用账号或重置密码时，撤销已有登录会话。

创建和重置账号的初始密码只显示一次，用户可登录后修改。当前要求至少八位，后续可按企业账号规范调整。

#### 19. 内部资料会不会发送给 DeepSeek？

按照目前采用的配置，普通和隐私资料问答都可以调用 DeepSeek，内部问题和命中片段可能离开本机。

分流后的资料问答不附带聊天历史，但工具调用等独立 Agent 路径可能使用近期上下文，不能把无历史外发作为整个系统的保证。分库主要控制分类和检索范围，目前没有全面自动脱敏。

#### 20. DeepSeek 会自己上网搜索吗？

当前接入模型 API，不能认为它自动具备联网搜索能力。公开搜索是独立功能，需要另外配置搜索服务。

后端从问题中提取允许使用的产品和通用技术词，获取网页结果后交给模型整理。本机检索、公开搜索和模型生成是三个不同环节。

### 六、可靠性与企业应用

#### 21. 模型、Redis 或数据库出问题怎么办？

模型失败时，有本地依据的部分流程可以返回简短摘录，无法确定则提示用户。Redis 不可用时可以降级到进程内缓存和限流，但多实例计数一致性会受影响。

数据库不可用时不能正常保存业务数据，缓存不能替代数据库。通过就绪检查、请求编号和轮转日志定位问题，排查时区分数据库、检索、OCR 和模型调用等阶段。

#### 22. 备份恢复是怎么做的？

本机 SQLite 使用在线快照，避免直接复制正在写入的数据库。备份包含资料原件与校验清单，恢复前验证文件路径和校验值。

恢复写入新目录，不直接覆盖运行系统，并清除旧登录会话。目前提供手动工具，没有自动建立定时备份或异机副本。

#### 23. 你怎么测试这个项目？

重点验证可能造成越权或业务错误的行为：user 无法调用管理接口、不能访问他人会话、停用资料不会通过缓存继续使用、文字图片正确分流、刷题结果保存，以及备份恢复和损坏校验。

另外需要真实截图和设备协议的业务验收。自动化测试通过证明被测行为符合预期，不能证明所有资料都能回答正确。

#### 24. 现在距离企业正式应用还缺什么？

账号权限、资料管理、会话记录、审计和本机备份等框架已经具备。后续重点完善真实资料质量、案例验收、协议解析覆盖率和企业数据使用政策。

还需要按使用规模落实服务器部署、HTTPS、监控告警、定时备份、恢复演练和数据库迁移机制。当前具备试用基础，仍需企业场景验收。

### 面试时可以展开的三个案例

| 案例 | 重点 |
|---|---|
| 图片输入统一 | 所有截图容易误走刷题，后来统一 OCR，再按文字结构区分题目与现场问题 |
| 资料停用 | 仅停用数据库中的资料不够，还需排除检索缓存和题库读取路径 |
